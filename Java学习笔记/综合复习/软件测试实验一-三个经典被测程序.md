# Java 软件测试实验一：三个经典被测程序

## 📖 知识点概述

本次实验用三个经典问题练习“程序设计 + 缺陷注入 + 测试用例设计”：

1. **三角形问题**：输入三条边，判断等边、等腰、直角、一般、非三角形或非法输入。
2. **NextDate 函数**：输入年、月、日，计算下一天，重点处理月末、年末和闰年。
3. **佣金问题**：根据枪机、枪托、枪管的月销量计算销售额，再按 10% / 15% / 20% 分级计算佣金。

这三个程序看起来简单，但它们分别代表了软件测试里最常见的三类缺陷：**边界条件错误、特殊规则遗漏、分段公式错误**。

## 🧠 关键要点

- **三角形问题**
  - 先检查三条边是否都在 `[1, 200]`。
  - 排序为 `a <= b <= c`，只需判断 `a + b <= c` 就能识别退化/非三角形。
  - 判断顺序建议：等边 → 等腰 → 直角 → 一般。
  - 浮点数不要直接用 `==`，应设置误差容限，例如 `1e-9`。
- **NextDate 函数**
  - 年份范围是 `[1600, 2100]`。
  - 闰年规则：`(year % 4 == 0 && year % 100 != 0) || year % 400 == 0`。
  - 先做日期合法性检查，再执行 `d = d + 1`。
  - 处理顺序：日进位 → 月进位 → 年进位。
- **佣金问题**
  - 月销量上限：枪机 70、枪托 80、枪管 90。
  - 每月至少售出一套完整产品（三种各至少 1 件）。
  - 输入以枪机数 `-1` 结束。
  - 分级累进公式：
    - `sales <= 1000`：`0.10 * sales`
    - `1000 < sales <= 1800`：`100 + 0.15 * (sales - 1000)`
    - `sales > 1800`：`220 + 0.20 * (sales - 1800)`

## 📝 代码示例

```java
// 三角形问题：排序后的退化判断
double x = Math.min(a, Math.min(b, c));
double z = Math.max(a, Math.max(b, c));
double y = a + b + c - x - z;
if (x + y - z <= 1e-9) {
    return "非三角形";
}

// NextDate：完整闰年判断
static boolean isLeapYear(int year) {
    return (year % 4 == 0 && year % 100 != 0) || year % 400 == 0;
}

// 佣金问题：分级累进计算
static double calculateCommission(double sales) {
    if (sales <= 1000.0) {
        return 0.10 * sales;
    }
    if (sales <= 1800.0) {
        return 100.0 + 0.15 * (sales - 1000.0);
    }
    return 220.0 + 0.20 * (sales - 1800.0);
}
```

## ⚠️ 注意事项 / 常见坑

- 三角形问题只判断 `a + b > c` 不够，必须使用排序后最大的边来判断退化边界；`1, 2, 3` 是典型测试数据。
- NextDate 只写 `year % 4 == 0` 会把 `2100` 年误判为闰年，导致输出不存在的 `2100-02-29`。
- 佣金第二档忘记减去 `1000`，会让 `(1000, 1800]` 区间的佣金被高估。
- 测试用例不能只覆盖正常路径，至少还要覆盖：下边界、上边界、刚好越界、非法输入、特殊年份和分段临界点。
- 缺陷注入是验证测试用例有效性的好方法：如果注入缺陷后所有用例仍然通过，说明用例覆盖不足。

## 📖 知识点概述

### 为什么先做分类

菜品必须属于某个分类：

- "宫保鸡丁" 属于 **川菜**（菜品分类 type=1）
- "商务套餐A" 属于 **套餐分类**（type=2）

**分类是菜品的爹。没有分类，菜品没法建。**

所以顺序是：**分类 → 菜品 → 套餐**。

## 🧠 关键要点

### 一、本模块的 5 个接口

| # | 功能 | 方法 + 路径 | 新东西 |
|---|---|---|---|
| 1 | 新增分类 | `POST /category` | 用 DTO（复习第 8 课） |
| 2 | 分类分页查询 | `GET /category/page` | ⭐ **分页**（全新） |
| 3 | 启用 / 禁用分类 | `POST /category/status/{status}` | 改一个字段 |
| 4 | 修改分类 | `PUT /category` | 动态 SQL（复习第 6 课） |
| 5 | 删除分类 | `DELETE /category/{id}` | ⚠️ 要先检查有没有关联菜品 |

### 二、会碰到的新东西

| 新东西 | 是什么 | 什么时候讲 |
|---|---|---|
| **分页查询** | 数据太多不能一次全查回来，要"一页 10 条" | 接口 2 时详细讲 |
| **公共字段自动填充** | 每张表都有 create_time / create_user，不该每个 Service 手写 | 分类做一半时讲（要用 AOP） |
| **关联检查** | "这个分类下还有菜品，不许删" | 接口 5 时讲 |

### 三、category 表结构

```sql
CREATE TABLE category (
    id          BIGINT       PRIMARY KEY AUTO_INCREMENT COMMENT '主键',
    type        INT          COMMENT '分类类型：1菜品分类 2套餐分类',
    name        VARCHAR(32)  NOT NULL UNIQUE COMMENT '分类名称',
    sort        INT          NOT NULL DEFAULT 0 COMMENT '排序',
    status      INT          COMMENT '状态：0禁用 1启用',
    create_time DATETIME     COMMENT '创建时间',
    update_time DATETIME     COMMENT '修改时间',
    create_user BIGINT       COMMENT '创建人id',
    update_user BIGINT       COMMENT '修改人id'
) COMMENT '分类表';
```

| 列 | 为什么这么设计 |
|---|---|
| `id` | 主键，和 employee 一样自增 |
| **`type`** | 1 = **菜品分类**（川菜/粤菜/饮品），2 = **套餐分类**（商务套餐/儿童套餐）。前端两个下拉框分开显示，靠这个字段区分 |
| `name` | `NOT NULL UNIQUE` → 不能空、不能重名（和 employee.username 一个道理） |
| `sort` | 排序号，前端按这个数字排。比如"热销"排第 1、"主食"排第 5 |
| `status` | 0 禁用 / 1 启用。禁用后用户端看不到 |
| `create_time` / `update_time` | 什么时候建的、什么时候改的 |
| **`create_user`** / **`update_user`** | ⭐ **谁建的、谁改的** ← BaseContext 的用武之地 |

### 四、🔑 BaseContext 终于要派上用场了

新增一个分类时，`create_user` 该填什么？**填"当前登录员工的 id"。** 那个 id 从哪来？

```java
BaseContext.getCurrentId()   // ← 拦截器验完 token 存进柜子的那个
```

**第 10 课写的东西，到这里开始真正干活。**

### 五、为什么会有"公共字段"这个概念

| 表 | create_time | create_user | update_time | update_user |
|---|---|---|---|---|
| `employee` | ✅ | ❌（早期漏了） | ✅ | ❌ |
| `category` | ✅ | ✅ | ✅ | ✅ |
| 以后的 `dish` | ✅ | ✅ | ✅ | ✅ |
| 以后的 `setmeal` | ✅ | ✅ | ✅ | ✅ |

**每张表都有这四个字段** → 每个 Service 都要手写一遍"填时间、填人"
→ **这就是"公共字段"，要抽出来统一处理**（用 **AOP**，到时候详细讲）。
